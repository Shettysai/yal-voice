A voice agent that reminds borrowers about EMIs

The browser talks to OpenAI Realtime over WebRTC. A small Node server mints the session key and runs the tools. Code owns the facts and the gates. The model owns the conversation.

      4 · Topology

      What talks to what, on the wire

      Two setups share the same prompt and tools. A live call runs in the browser. An eval run is one Node process with no browser and no server.

      a · Live call

      Audio never touches our serverMic and agent audio flow only between the browser and OpenAI.
      The real key stays on the serverThe browser gets a client secret that expires after 10 minutes.
      Tools run on the serverThe browser forwards each function call to /api/tool. Call state lives there.

      b · Eval run

      The text eval tests the same prompt, tools and gates. It cannot see VAD, barge-in, mishearing or audio latency.

      Live voice: not measuredThe call page records it per turn. Numbers go into docs/RESULTS.md after demo calls.

      How one sample is measured

      Meters sample every 10 ms in call.js. The clock starts at the last sound, not at the VAD event, so the 500 ms counts. When a tool returns, a new sample runs from the result to the next agent sound.
